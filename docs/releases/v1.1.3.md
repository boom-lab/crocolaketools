Bug-fix release for `spray2parquet` and `saildrones2parquet`. No change to the
data product or to the configuration format.

## Fixed

- `spray2parquet` and `saildrones2parquet` restarted their Dask client with
  `config_cluster`, a name removed in v1.1.0 when the config files were
  renamed. `spray2parquet` failed with `NameError` after the PHY
  `prepare_data` step, and `saildrones2parquet` after the PHY conversion.
  Both now restart the client with the `SPRAY_GLIDERS` and `SAILDRONES`
  settings from `dask_cluster.yaml`, as they do at start-up.
- `spray2parquet` without `--config` set `'db': 'GLODAP'` in its
  configuration, which `ConverterSprayGliders` rejects with `ValueError`. It
  now sets `'db': 'SprayGliders'`.

## Added

- `spray2parquet -d/--db-type {PHY,BGC}` converts only that type. Without
  `-d`, it converts PHY, then BGC, as before. The BGC conversion now also
  restarts the Dask client between `prepare_data` and `convert`, as the PHY
  conversion already did.

## Upgrading

Deployments running the Spray gliders or Saildrones conversion with v1.1.0 to
v1.1.2 should upgrade. Jobs can now run PHY and BGC as separate
`spray2parquet -d PHY --config` and `spray2parquet -d BGC --config` calls.
