Bug-fix release for `download_spraygliders` and `spray2parquet`. No change to
the data product or to the configuration format. The local filenames of the
Spray Level-3 files are unchanged.

## Fixed

### spray2parquet

- `spray2parquet` failed in `prepare_data` with `TypeError: '<' not supported
  between instances of 'NoneType' and 'datetime.datetime'` when a chunk of
  `chunk_profile` profiles had `time` (or `time_uv`) missing for every
  profile. xarray 2025.1.2 and later (including the pinned 2025.7.0) cannot
  encode an all-NaT datetime variable that carries `units`. Any
  `chunk_profile` small enough to produce such a chunk was affected: the
  current Spray files have 64 all-NaT chunks at `chunk_profile: 20`. The
  default, 5000, produced none on current data. `prepare_data` now opens the
  source files with `decode_times=False`, so the chunks keep the raw numeric
  times with their `units` and `calendar` attributes. The conversion reads
  the chunks with default decoding, as before, so the parquet output is
  unchanged.
- A failed `prepare_data` or `convert` left the temporary directory
  (`tmp_path`) behind, and the next run stopped with `Temporary path ...
  already exists`. `spray2parquet` now removes the temporary directory when
  either step fails, then re-raises the error. If `tmp_path` already existed
  when the run started, the run still stops with the same error and leaves
  that directory alone, since it may belong to another run.

### download_spraygliders

- The Spray server renamed three Level-3 files: `binnedFLEAT` now serves
  `fleat_v1.1.nc`, `binnedCalypso` serves `calypso.nc` and `binnedOKMC` serves
  `okmc_v1.1.nc`. `download_spraygliders` requested the old names, skipped
  these three datasets with a warning and exited 0. It now reads each
  dataset's ERDDAP file listing (`files/<datasetID>/.csv`) and downloads the
  single `.nc` file it holds, whatever its name. The file is still saved as
  `FLEAT.nc`, `Calypso.nc` and `OKMC.nc`.
- Existing files were never updated unless `--overwrite` was given. A file is
  now downloaded if the local copy is missing, its size differs from the
  server's, or its modification time is older than the server's. After a
  download, the local modification time is set to the server's. Unchanged
  files are skipped. `--overwrite` still forces a re-download.
- `binnedMabSwot` was missing from the download list, so `mab_swot.nc` was
  never updated. It is now downloaded.
- Failures are now reported. A dataset fails if its listing cannot be read,
  if the listing holds zero or several `.nc` files, if the download fails, or
  if the downloaded size differs from the listing. The other datasets are
  still downloaded, a summary of the failed datasets is printed at the end,
  and `download_spraygliders` exits with status 1.

## Added

- `download_spraygliders` warns about binned datasets on the server
  (`allDatasets`, `datasetID=~"binned.*"`) that are not in `SPRAY_FILES`. They
  are not downloaded.
- `--files` accepts ERDDAP dataset IDs as well as local filenames, e.g.
  `--files FLEAT.nc binnedMabSwot`.

## API changes

- `SPRAY_FILES` now maps ERDDAP dataset ID to local filename
  (`"binnedFLEAT": "FLEAT.nc"`). Before, it mapped local filename to remote
  path. The `fnames` argument of `DownloaderSprayGliders` and
  `download_spraygliders` follows the new format.
- `download_spraygliders()` returns `(paths, failed)`, where `failed` maps
  dataset ID to the reason it failed. `DownloaderSprayGliders.spray_download()`
  still returns the list of paths and stores the failures in `.failed`.
- `DownloaderSprayGliders.get_url()` takes a dataset ID.

## Upgrading

Deployments that download Spray data should upgrade: with v1.1.3 and earlier,
`FLEAT.nc`, `Calypso.nc`, `OKMC.nc` and `mab_swot.nc` are not updated. The
first run after upgrading downloads every file whose local modification time
is older than the server's.

Deployments that run `spray2parquet` with a `chunk_profile` below the default
should upgrade. A `tmp_path` left behind by a failed run with v1.1.3 or
earlier must still be removed by hand before the first v1.1.4 run.
