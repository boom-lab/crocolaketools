Bug-fix release for `merge_crocolake`. No change to the data product. The merge now
reads its own Dask cluster key (see below).

## Fixed

- `merge_crocolake --config` passed the CrocoLake path to
  `crocolakeloader.Loader` as a `pathlib.Path`, which v1.1.x returns from the
  configuration. The loader joins `db_rootpath` to strings with `+`, so the
  PHY and BGC merges failed at start-up with
  `TypeError: can only concatenate str (not "PosixPath") to str`. The path is
  now converted to a string before it reaches the loader.
- Without `--config`, a missing `-i` or `-o` is now a command-line error.
  Before, a missing `-i` reached the loader as `None`.
- The merge used the `SPRAY_GLIDERS` Dask cluster settings. It now reads
  `CROCOLAKE` from `dask_cluster.yaml`, for both PHY and BGC.
- The log file was written to the current working directory. It is now
  written next to the output directory: `outdir_pq` `/data/CROCOLAKE_PHY/`
  logs to `/data/PHY_CROCOLAKE.log`. It is not written inside `outdir_pq`
  because the merge empties that directory before writing.

## Configuration

- `CROCOLAKE` in `dask_cluster.yaml` is now used by the merge. It is
  optional: if it is missing, the merge logs a warning and uses
  `SPRAY_GLIDERS`, as before. `dask_cluster.example.yaml` now includes it.
  Deployments that already define `CROCOLAKE` will run the merge with those
  settings instead of the `SPRAY_GLIDERS` ones.

## Testing

- New `tests/test_merge_crocolake.py` runs the merge, including `main()` with
  `--config`, against a stand-in loader that handles `db_rootpath` the same
  way as the real one. It is part of the downloader/config CI job.

## Upgrading

Deployments running the merge with v1.1.0 or v1.1.1 should upgrade. Check
that `CROCOLAKE` in `dask_cluster.yaml` is sized for the full merge, or add
it, since the merge no longer uses the Spray gliders settings when it is
present. Jobs that read the merge log
from their working directory should read it from the parent of `outdir_pq`
instead.
